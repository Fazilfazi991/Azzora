## Session issue and response codes

The earlier CLI-created Preview had no Git-branch URL, but the staging authentication initialization required one. The revised check accepts the exact immutable deployment hostname provided by Vercel for the approved dedicated Preview project, preserving origin, CSRF, MFA, project/environment and permissions checks. On the new Preview, the actual `/api/staging/auth/session` endpoint returns 401 when signed out; `/api/staging/session` is not a supported endpoint and returns 404. Previous generic transport-stage logging did not disclose the thrown reason; the controlled configuration and before/after behavior support this root cause.

403 responses in the access tests were expected permission or origin denials. A 409 represented optimistic concurrency protection; one of two competing writes succeeded. A 423 represented a blocked operation under an unapproved policy, including VAT and unsupported refund/credit paths. None was converted into a success.

## Verification

On the final Preview, four fictional roles signed in with correct roles and snapshots. Owner and Accountant completed MFA; Manager and Engineer used their expected staging assurance. Cross-origin login was denied and logout invalidated sessions. Owner desktop and Accountant mobile browser login/MFA/refresh/logout passed through an authenticated Vercel CLI test proxy; representative Manager desktop and Accountant mobile route navigation also passed. This is not direct network-path or complete hosted browser regression coverage. Authorized Accountant access to a known fictional original succeeded; site staff were denied it. A real Manager staging JWT was denied service-only RPC/private-schema access. Cross-company hosted access was not verified: only one fictional company exists and the supported staging APIs do not create a second tenant.

On the final protected Preview, a serial run of 49 fictional hosted financial API checks passed (staging version 330 to 373). The Manager and Accountant saw the same invoice and receipt balance; purchase bills, supplier payments, reversals, concurrency, duplicate prevention and balanced financial reports were checked. Twelve additional final-Preview API checks passed, including independent project-expense approval, Accountant posting, bank-to-cash transfer and restricted-client denials without balance changes. Final hosted invoice, P&L and Balance Sheet PDFs were rendered and visually inspected as single-page fictional examples without obvious clipping. The renderer reported missing display fonts; this is not font-fidelity certification or approval of legal tax invoices.

An initial financial run on the final Preview stopped with a 403 after its Manager provider session was revoked. A separate test performed an unscoped provider logout three seconds beforehand; the database reported the affected session revoked or downgraded. This is strong evidence of test interference, but logs do not prove which request revoked the session. The failed run remains recorded. A separate mobile browser sign-in attempt timed out without a request ID or corresponding runtime error; its retry passed, but the cause is not established.

At the integrated application checkpoint, 1,187 unit tests across 93 files, TypeScript, ESLint and the Vercel Preview build passed. The complete Saturday operational browser suite passed twice across four widths with 136 checks each; a separate 390px run passed 34. The original intermittent timeout did not recur, so its root cause is not established. The document-entry suite passed 21 checks, and the 12-item browser review passed nine checks through local HTTPS with authorized fictional staging. Full Manager and Accountant hosted browser regressions, direct Chrome network-path coverage, real-time expiry and true hosted cross-company tests are not established by these results.

## Recovery and cutover

The synthetic encrypted restore reconciled source and restored Trial Balance, Balance Sheet, P&L, records, journals and an original file. It did not exercise production Auth, infrastructure, scheduled exports or offsite restore. The approved Free Supabase plan does not provide the managed daily backups and PITR needed to assume recovery exists. The backup schedule, secure offsite destination, keys and custody, retention, failure alerts, RPO/RTO, identity and object recovery, and production recovery rehearsal remain unestablished. See `BACKUP-CUTOVER-RUNBOOK.md` and `MIGRATION-RECOVERY.md`.

`ACCOUNTING-DECISIONS.md` is the owner/accountant decision sheet. VAT/TRN, legal invoice treatment, authority, recognition, advances, allocations, opening balances and cutover remain unapproved. The import workflow is review/quarantine only; actual publication into company records and opening postings remain blocked. Production migration, real-user onboarding, real AI document processing and real financial posting remain disabled. Existing live Manager and Accounts aliases and GitHub main were not changed.

**Production decision: NO-GO.** Do not request real-user onboarding, real-data import or real-posting activation until the unresolved security/hosted acceptance, operational recovery, accounting policy, implementation and reconciled cutover gates are completed and independently approved.
