It must not be presented as active monitoring until the complete backup writer, owner authorization, alert delivery and missed-backup simulation are tested end-to-end.

## After the full writer and secure key custody exist

1. Owner signs into the approved Google account and creates a standalone Apps Script project. Copy the reviewed `backup-watchdog.gs`, add the **Advanced Drive service v3**, and keep the project private to the owner. Do not deploy it as a web app.
2. In private Script Properties set `OWNER_EMAIL`, `ALERT_EMAIL`, `FOLDER_ID`, the exact environment `PROJECT_REF`, an owner-approved `MAX_BACKUP_AGE_HOURS`, and `MONITOR_HMAC_KEY`. Both email properties must equal the explicitly approved address hard-coded in the script; a mismatch halts without sending any message. Changing recipients requires a reviewed code change and authorization. The key must be independently generated 32 random bytes, base64url encoded, stored privately, and securely shared with the writer through its secret store; never paste it into chat, source control or job logs. Protect editing rights: anyone who can read/edit Script Properties can forge or suppress monitoring evidence.
3. Owner grants the script required Drive read and Mail send access via Google's authorization dialog. After the full backup writer is configured, run `sendTestAlert` once, then confirm the actual received message at the approved mailbox. This proves a test message only, not automatic alert delivery or restore. The user's task explicitly requests a test email; preserve an execution result and mailbox evidence without capturing unrelated mail.
4. Run `monitorBackup` with a genuine recent **fictional** full-source status, then simulate a missing status or expired signed timestamp using an isolated test folder and separate test key. Confirm an alert arrives, then independently check status and integrity after the genuine scheduled workflow. Do not remove or alter real backups during a simulation.
5. Create an installable **time-driven** trigger for `monitorBackup` at the approved check frequency. Verify trigger execution history and receipt of a deliberately simulated missed-backup alert. Monitor the monitor: an Apps Script account/permission/trigger failure can prevent both checking and emailing; execution failure notifications and periodic owner review are needed, and do not prove continuous operation.

## What the check does and does not prove

The monitor verifies the folder is private and owner-owned, requires exactly one small signed `azzora-backup-status-v1.json` marker, checks full-capture flags and project/time scope, and checks the encrypted archive's owner, privacy, exact parent, byte size and Google Drive server-computed MD5 against signed metadata. It checks overall Drive capacity and warns at 85%. HMAC binds fields to a shared key. A missing, stale, invalid or inaccessible marker/archive and Drive-auth failure lead to a generic email; secrets and provider errors are not emailed.

The marker's SHA-256 is authenticated as an assertion; Apps Script does not download the archive or recompute SHA-256. The marker does not prove all database schemas, Auth, objects or journals were captured, that a job actually ran without a compromised signing key, or that restoration succeeded. An isolated real scheduled restore and independently controlled proof remain required. A failed upload or expired writer credential that leaves the preceding valid marker in place is detected only once that marker becomes stale, not immediately; the configured freshness threshold and randomized monitor interval determine the additional delay. The writer must never sign a full-capture marker for the current business-only archive. A failing MailApp authorization/quota or a failure before the script executes may prevent alert delivery.

Google states consumer-account limits include 100 email recipients/day, 90 minutes/day total trigger runtime and 6 minutes/execution; quotas can change and may already be shared with other scripts. Installable triggers can run at a randomized time within the selected hour and run as their creator. Verify current limits and actual account use before activation: [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas), [installable trigger timing](https://developers.google.com/apps-script/guides/triggers/installable), [MailApp quota](https://developers.google.com/apps-script/reference/mail/mail-app).
